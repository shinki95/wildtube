1목적과 쓰는 사람

같은 곡을 두 연주로 나란히 듣고, 어디가 왜 다른지 귀로 확인하는 곳이에요.

지금: 사장님. 집에서 폰으로 공부하듯 들어요. 한 손으로 누르고, 악보와 설명을 읽으면서 A와 B를 번갈아 들어요.
나중: 클래식 팬 커뮤니티. 오픈소스처럼 누구나 짝과 비교 페이지를 더해요(JSON만 추가, 화면 코드는 그대로). 처음 온 사람도 설명 없이 상자를 뒤져 판을 꺼낼 수 있어야 해요.

2사용 사례 7개

U1작곡가로 찾아 판을 꺼내고 비교 페이지를 연다.
작곡가 칩 '브람스'→상자가 브람스 판만→꺼내기→비교 페이지 열기
U2연주자 이름으로 찾는다.
검색 '굴드'→걸러진 판 첫 장으로→◀ ▶ 또는 아래 목록→꺼내기
U3A-Z로 상자를 뒤적인다.
글자 'M'→휘리릭 넘어감→다음 ▶ 몇 번→마음에 드는 판 꺼내기
U4내 목록에 담고 나중에 다시 본다.
꺼낸 판→☆ 내 목록→(다음 날) 장르 '내 목록'→담은 판만
U5비교 페이지에서 파트마다 A 듣고 B 듣는다(턴테이블 2대).
단계 카드 읽기→A 듣기→A 판 회전→B 듣기→B 판 회전, A 정지→들은 뒤 펼치기
U6같은 구간을 A와 B로 빠르게 번갈아 듣는다(전환).
A 재생 중→A↔B 바꾸기→B가 같은 구간에서→다시 바꾸기
U7비교 페이지가 없는 짝은 유튜브에서 찾거나 요청한다.
꺼내기→A 유튜브에서 찾기/B 유튜브에서 찾기→비교 페이지 요청

6턴테이블을 진짜처럼: 전문 디테일

참고한 것. 3D 캐릭터를 푸딩처럼 말랑하게 만든 웹 장난감: 손으로 이리저리 돌려 보고, 누르면 물리적으로 흔들리고, 말랑함(단단함·내부 감쇠)을 슬라이더로 직접 바꿔요. 배울 점은 세 가지예요. 진짜 물리, 손으로 만지는 맛, 전문가가 쓰는 매개변수를 그대로 보여 주기.

그래서 턴테이블도 그럴듯한 그림이 아니라 실제 기계처럼 움직이게 해요. 숫자는 일반적인 다이렉트 드라이브 턴테이블 사양에서 가져왔어요(출처는 맨 아래 참고 목록).

8스타일 원칙

조작 요소는 리퀴드 글라스. 반투명 패널, 블러와 채도 올림, 얇은 밝은 테두리, 안쪽 하이라이트, 떠 있는 그림자. 눌리면 살짝 들어가고, 손을 올리면 빛이 스쳐요. 블러는 조작 바·칩 묶음·상세 카드·고정 영역에만 쓰고 판에는 쓰지 않아요.
색 규칙. A 늘 남색 B 늘 적갈색, A가 먼저·왼쪽. 배경은 크림·나무·금색 안에서 부드러운 그라데이션과 은은한 빛 번짐.
아이콘과 글자 함께. 이전, 다음, 재생, 일시정지, 별, 유튜브 찾기, 열기는 아이콘 옆에 글자를 늘 보여요. 숨은 제스처만으로 되는 기능은 없어요.
움직임 시간. 넘기기 0.6초(살짝 튕기는 곡선), 휘리릭 한 장 0.07초, 꺼내기 0.6초(판이 돌며 나옴). 턴테이블은 6장의 실제 사양을 따름: 33⅓rpm(한 바퀴 1.8초), 시작 0.7초, 정지 기본 1.0초, 톤암 하강 기본 0.8초.

로컬·일부 기기에서 영상이 안 나와 판만 돈다영상 오류 상태를 따로 두고, 오류가 오면 톤암을 올리고 판을 멈추고 '알려 주세요' 링크를 보여 줌

10정해 주실 것

1. 턴테이블 영역: (가) / (나) / (다) 중 하나추천 (다), 넓은 화면은 (나)

이유: 판을 잡고 돌리는 손맛을 살리려면 판이 커야 해요. (다)는 판이 각 약 165px이고 (나)는 약 80px인데, 손가락 터치 최소 크기(보통 44px)를 생각하면 80px 판에서는 둘레를 따라 돌리기가 어려워요. 크로스페이더로 번갈아 듣기도 한 번에 돼요.

바뀐 판단: 앞 버전에선 영상이 늘 보이는 (나)를 추천했어요. (다)에서는 폰의 모니터를 고정 영역 바로 아래에 붙이고, 폭 900px 이상 화면에서는 자동으로 두 대 사이(나)에 둬서 이 약점을 줄여요. 그래도 폰에서 글을 읽느라 내리면 영상이 화면 밖으로 나가요. 이것이 규정에 걸리는지 확실하지 않아 남은 위험으로 적어 둬요(최소 크기 200×200은 지킴).

2. U6 A↔B 바꾸기를 이번에 넣을까요추천: 넣기(구간 처음부터)

이유: 번갈아 듣기가 이 페이지의 핵심이라 버튼 하나로 바로 바꾸는 효과가 커요. 같은 마디로 정확히 옮기는 전환은 비교 페이지에 마디 시간표를 더한 뒤 다음에 넣어요.

3. 3D 수준추천 (2) three.js 진짜 3D

(1) CSS 입체: 가볍고 빠름, 돌려 보기·물리는 흉내만. (2) three.js: 돌려 보기·판 잡기·톤암 물리가 진짜로 됨.

이유: 참고 영상의 핵심이 '손으로 만지는 진짜 물리'라서 (2)여야 그 맛이 나요. 물리 계산은 그림과 따로 만들어서, 느린 기기에선 같은 계산으로 (1)을 그리는 가벼운 모드로 바로 바꿀 수 있어요.

4. '빠르기 맞추기'를 이번에 넣을까요추천: 넣기, 기본 꺼짐

이유: 빠르기 차이를 지우고 소리만 비교하는 건 전문가식 듣기의 핵심이고, 계산은 이미 있는 마디 시간으로 돼요. 다만 유튜브가 세밀한 속도를 안 주는 영상이 있을 수 있어서, 구현 첫날 비교 페이지 6편 영상의 지원 속도 목록을 실제로 확인하고, 안 되는 영상에선 스위치를 흐리게 둬요.

11지금 화면 점검에서 나온 것 (구현 첫 단계에서 먼저 고침)

지금 올라가 있는 페이지를 폰(390px), 태블릿(768px), 컴퓨터(1280px)로 재 본 결과예요. 턴테이블을 고르기 전에도 고칠 수 있는 것들이라 구현 1단계로 둬요.

  1. 비교 페이지 첫 화면에 누를 게 없어요. 첫 A/B 구간 버튼이 폰으로 약 3화면 아래(2,390px)에 있어요. -> 첫 화면에 "1단계 A 듣기 / B 듣기"를 바로 두고, 비교 페이지 칩은 한 줄 가로로.
  2. 글자가 작아요. 대부분 13~14px라 8장의 "본문 16px 이상"과 어긋나요. -> 본문 16px 이상, 보조 글 14px 이상.
  3. 누르는 곳이 낮아요. 칩·버튼 높이 36px. -> 44px 이상.
  4. 비교 칩 이름이 콜론에서 잘려요("바흐 골드베르크 변주곡:"). -> 칩용 짧은 이름을 따로.
  5. 작곡가 칩이 라틴 성 순서인데 한글로 보여 순서가 뒤죽박죽처럼 보여요. 100개 넘는 칩이 A-Z 줄과 역할이 겹쳐요. -> 작곡가는 A-Z 줄과 검색으로 합치고, 칩에는 라틴 이름을 같이 적어요.
  6. 글꼴이 4종이에요. -> 제목 세리프 1종, 본문 1종으로.
  7. 컴퓨터 화면에서 첫 판일 때 왼쪽 절반이 비어요. -> 넓은 화면은 상세 카드를 옆에.
  8. 폰 첫 화면에서 소개 3줄 때문에 꺼내기 버튼이 맨 아래에 붙어요. -> 소개는 1줄.

더 해 볼 만한 것(골라 주세요에 추가). 여러 연주의 빠르기 곡선을 겹쳐 보여 주고 그래프를 누르면 그 자리부터 듣는 방식이 있어요. 우리는 마디 시간을 이미 재 두었으니, "들은 뒤" 막대 대신 곡 전체 빠르기 곡선(A 남색, B 적갈색)을 넣고 누르면 그 마디부터 재생할 수 있어요. 또 위아래 버튼으로 같은 위치에서 연주자만 바꾸는 방식은 U6(A↔B 바꾸기)의 원형이에요. 비교 도구들은 대개 폰에서 약해서, 폰에서 잘 되는 비교 도구가 우리 자리예요.

구현 방법. 한 번에 한 가지를 고치고, 고칠 때마다 390/768/1280 세 폭으로 찍어 비평만 먼저 한 뒤 큰 것만 고쳐요. 한 화면에 이 고리를 2번까지만 돌려요.
